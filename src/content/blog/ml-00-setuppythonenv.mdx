I use conda rather than `venv` for anything touching CUDA. Not out of loyalty —
`venv` is lighter and I prefer it elsewhere — but conda installs its own CUDA
runtime libraries alongside the Python packages, which is the difference
between PyTorch finding the GPU and PyTorch shrugging. I lost an evening to
that before giving in.

Miniconda, not Anaconda: the full distribution ships hundreds of packages you
will not use.

## Install Miniconda

```sh
mkdir -p ~/miniconda3
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh -O ~/miniconda3/miniconda.sh
bash ~/miniconda3/miniconda.sh -b -u -p ~/miniconda3
rm ~/miniconda3/miniconda.sh
```

`-b` runs it unattended (no licence prompt to page through), and `-p` pins the
install location so it does not sprawl into your home directory.

## Put it on PATH

```sh
echo 'export PATH="$HOME/miniconda3/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

## Create the environment

```sh
conda create --name envname python=3.11
conda init
```

`conda init` writes the shell hook that makes `conda activate` work, and it
only takes effect in a **new** shell. Restart the terminal here — this is the
step that trips people up, because `conda activate` fails in the same session
with an error that suggests the install went wrong.

```sh
conda activate envname
```

Pin the Python version explicitly. Letting conda pick means a different version
per machine, and ML packages care about that far more than most.

## Packages

The stack I start most projects from:

```sh
# numerical / data
pip install numpy pandas scipy matplotlib seaborn scikit-learn

# deep learning — check pytorch.org for the right CUDA build
pip install torch torchvision torchaudio

# serving
pip install fastapi uvicorn python-dotenv sqlalchemy psycopg2-binary

# scraping
pip install beautifulsoup4 selenium
```

Install `torch` from the index that matches your CUDA version rather than plain
PyPI — [pytorch.org](https://pytorch.org/get-started/locally/) generates the
command. The default wheel may not match the driver you have.

### On pip freeze

I used to paste `pip freeze > requirements.txt` output straight into these
notes. It is the wrong artefact to share. `freeze` dumps the fully resolved
tree, so you get eighty pinned lines including every `nvidia-cu12-*`
transitive dependency, hardware-specific builds like `torch==2.7.0+cu128` that
will not install on a machine with a different CUDA version, and no signal
about which packages you actually asked for.

Keep the list of things you chose. Let the resolver work out the rest:

```sh
pip install -r requirements.txt
```

`pip freeze` still earns its keep for locking a deployment to an exact known
state — just keep it as a separate lock file, not as the thing you read.
