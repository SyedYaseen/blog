I wanted a staging environment on the old laptop under my desk without opening
a hole in my home router. A Cloudflare tunnel does that by inverting the
connection: the `cloudflared` daemon dials **out** to Cloudflare and holds the
connection open, and inbound requests come back down that pipe.

Which means:

- No port forwarding on the router. The home network keeps its inbound deny-all.
- No listening ports exposed to the internet at all — not even 80 and 443.
- TLS certificates handled by Cloudflare, free, with no renewal to remember.
- Your home IP address is never published in DNS.

## Cloudflare dashboard

First, move the domain's nameservers to Cloudflare — the tunnel needs
Cloudflare to be authoritative for DNS.

Then create the tunnel, at **Zero Trust → Networks → Tunnels**:

- Create Tunnel, and copy the `token` it gives you. That is the credential the
  daemon authenticates with; it goes in the next step.
- **Public Hostname → Add public hostname**
  - Hostname `*.domainname.com` for a wildcard subdomain
  - Service `HTTPS://localhost:443`
  - **Additional application settings → TLS → Origin server name** →
    `*.domainname.com`

That origin server name is easy to skip and it will break TLS if you do —
Cloudflare validates the certificate your server presents against this name.

Adding the hostname creates the DNS record automatically. If it does not, add
it by hand: `NAME = *`, `CNAME = <tunnelId>.cfargotunnel.com`.

Repeat for the apex domain. One tunnel can serve as many hostnames as you like,
so there is no reason to run more than one.

## The cloudflared service in Coolify

- Create a `cloudflared` service and set the tunnel `token` as an environment
  variable.
- **Server → Wildcard Domain** → `https://domainname.com`. It must be `https`
  even though the tunnel terminates TLS.
- **Settings → Instance Settings → Instance's Domain** →
  `coolify.domainname.com`
- Each deployed service gets its own domain:
  `https://anysubdomain.domainname.com`

Services only need their ports published if you want to reach them directly
from the local network. Tunnel traffic does not require it — the daemon reaches
them over Docker's internal network.
